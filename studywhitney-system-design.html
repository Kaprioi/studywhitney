StudyWhitney system design

How the app in /Applications/StudyWhitney.app (v0.2) is built, and how the Whitney cat on your screen works. Pieced together from the app bundle.

Web pages (HTML/JS in WKWebView)Native code (Swift)Storage and outside services

The three layers

  • Swift shell. A small native Mac binary (arm64, ad-hoc signed, id local.studywhitney.app). It opens the windows, adds the menu bar item, makes network calls, prints, and keeps the Claude key in the Keychain. It has no study logic of its own.
  • Main window. index.html is the actual app: classes, tests, homework, notes, quizzes and the practice exam writer. It pulls KaTeX (math) and pdf.js (textbook reading) from cdnjs.
  • Whitney. pet.html runs in a second, transparent web view that floats over your desktop. The cat is pixel art drawn on a canvas 12 times a second.

How the cat on your screen works

  1. The shell opens a borderless, transparent PetPanel (an NSPanel) that covers the screen and floats above other windows.
  2. Most of that panel lets clicks pass through. Each time the cat or its speech bubble moves, the pet page sends their rectangles to the shell (rects). A timer checks the mouse position and only catches clicks inside those areas, so you can click "through" the rest of the screen.
  3. The shell tells the pet where the top of the Dock is (setFloor) so Whitney walks along it. Where you drag the cat is saved in the pet's own storage (pos).
  4. Every 60 seconds the pet asks for data (getData). The shell runs __petData() in the main window, which returns each class's tests and homework, and passes the result back with petData().
  5. Reminders: she speaks up about tests within 7 days and homework due today or tomorrow. Each reminder fires once (tracked in alerted), and "Snooze 1 hr" quiets her.
  6. Click her for a summary (next test, open homework). The "Quiz me", "My scores" and "Open app" buttons send open, and the shell brings up the main window and calls __openFromPet to go to that class.
  7. Moods: idle, walk (wanders about ±150px from home), happy, alert (for reminders), and sleep after 4 minutes untouched.
  8. To hide her, right-click and choose "Hide me" (which sends hide). Bring her back with "Show Whitney on Desktop" in the menu bar or the switch in the app (togglePet).

How a practice exam gets written

  1. You choose a past exam to copy the style of, and/or textbook sections or pages, plus lecture notes.
  2. The page loads the files you attached from IndexedDB. A past exam goes in as a PDF or image. For textbooks, pdf.js pulls out the text of the sections you asked for.
  3. callClaude() sends the request through the app bridge (type: 'claude'). The page never touches your API key.
  4. The shell reads the key from the Keychain and POSTs to api.anthropic.com/v1/messages using claude-opus-5-5, high effort, with a JSON schema for the exam.
  5. The reply comes back through __claudeDone(id, text). The exam is saved with the class, and you can view it, print it, or open the answer key.

Where your data lives

  • Classes, tests, homework, notes, generated exams: one JSON blob in the main window's localStorage.
  • Attached files (syllabi, textbooks, past exams): IndexedDB studywhitney-files.
  • Claude API key: macOS Keychain, readable only by the native code.
  • Pet state (where she sits, which reminders she's given): the pet page's own localStorage.
  • Everything stays on your Mac. The only data that leaves it is what goes to Claude when you generate an exam, plus the KaTeX and pdf.js downloads from cdnjs.
