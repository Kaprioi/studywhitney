Study Buddy

An AI study agent that knows your classes. Give it your courses, textbooks, syllabus and lecture notes, and it organizes your work, quizzes you, writes practice exams, and texts your phone before every test.

What it has to do

  1. Know each class. Course name, professor, textbook, syllabus, and which chapters have been covered so far.
  2. Take in material. Lecture notes (typed, PDF, slides, or photos of handwritten pages) and textbook chapters.
  3. Help you review. Chat that answers from your own material with citations, plus summaries, flashcards and quizzes.
  4. Make practice exams scoped to what the real exam covers, then grade them and point to the weak topics.
  5. Track dates. Read exam and due dates from the syllabus, and let you add others by chat ("midterm moved to the 24th").
  6. Remind you with push notifications on your phone, plus a study plan counting down to each exam.

Architecture

One mobile app talks to one backend. The backend has three jobs: run the agent, process uploads, and fire reminders on time.

Data model

  COURSE ||--o{ QUIZ : "practice sets"
  QUIZ ||--o{ ATTEMPT : "your answers"

The link that makes it smart is EVENT covers TOPIC. When the agent builds a practice midterm, it only pulls chunks tagged with the topics that midterm covers. TOPIC also stores covered_on, so "what we've covered" is a date filter.

The agent

A single agent with a small, sharp set of tools. The system prompt carries your course list, upcoming events and today's date, so it can answer "what should I study tonight?" without a tool call.

ToolWhat it does
search_materialVector + keyword search, filtered by course, topic or date range. Returns chunks with source and page.
list_courses / get_courseCourses, textbook, syllabus topics, what's been covered
mark_covered"We did chapter 6 today" → updates topic coverage
create_event / update_eventAdd or move an exam or deadline; reminders are regenerated automatically
generate_quizFlashcards, multiple choice, short answer or full practice exam from selected topics
grade_attemptGrades answers against a rubric, records per-topic scores
get_weak_topicsLowest-scoring topics across recent attempts, used for the study plan

Rule for every answer: cite the lecture or page it came from. If nothing relevant is in your material, the agent says so before falling back to general knowledge. This is the main defense against wrong answers.

Key flows

1 · Adding a class

Upload the syllabus PDF. The ingestion worker extracts the schedule, and the agent proposes topics and exam dates for you to confirm. Confirmed exams create reminders right away.

2 · Uploading lecture notes

sequenceDiagram
  participant P as Phone
  participant A as API
  participant W as Ingestion worker
  participant D as Database
  P->>A: upload photo/PDF + course
  A->>D: save document (status: processing)
  A-->>W: enqueue job
  W->>W: OCR / extract text, split into chunks
  W->>W: tag chunks with topics (Haiku), embed
  W->>D: save chunks, mark topics covered
  W-->>P: push "Lecture 7 notes are ready to review"

3 · Practice exam

  1. You ask for a practice midterm. The agent looks up the event and its topics.
  2. It retrieves chunks for each topic, weighted toward topics with more lecture time and toward your weak spots.
  3. It writes questions in the style of past exams if you uploaded any, each with an answer key and source.
  4. You answer in the app. grade_attempt scores it and updates per-topic mastery.

4 · Reminders

When an exam is created, the scheduler writes rows into reminders: 7 days, 3 days, 1 day, and the morning of. Each one carries a short plan ("Tonight: chapters 5–6 flashcards, 20 min"). A daily review nudge comes from spaced repetition on flashcards you got wrong. Moving an exam deletes unsent reminders and writes new ones.

You also get a calendar feed (.ics link) so dates show up in Apple or Google Calendar.

Decisions and risks

  • Textbooks are big. Ingest chapter by chapter as they're assigned, not the whole book on day one. That keeps costs down and search focused.
  • Copyright. Students upload their own copies for their own study. Material is private to the account and never shared between users.
  • Handwriting. Claude vision reads it well, but the app shows the extracted text so you can fix mistakes.
  • Cost control. Use prompt caching on the course context, Haiku for bulk tagging, and cache generated quizzes.
  • Notifications on iOS need a real Apple developer account for production push. For a quick personal MVP, ntfy.sh or a Telegram bot sends phone alerts with no app store step.

Build order

Phase 1
Courses, events, reminders and push. Small, and useful on day one.
Phase 2
Upload pipeline and grounded chat with citations.
Phase 3
Quizzes, practice exams, grading and weak-topic tracking.
Phase 4
Syllabus auto-import, study plans, spaced repetition, calendar feed.

These phases split cleanly into parallel tasks (mobile app, API, ingestion worker, scheduler), which is the kind of work firstmate can hand to a crew of agents, each in its own Herdr tab and git worktree.
